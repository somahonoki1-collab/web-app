# 成長指標の調査と初版の数式案

調査日：2026年10月7日。対象は「一定期間の筋力の伸びを仲間内で競う」機能。アプリへの実装はまだ行っていない。

## 1. 結論

**数式は作れる。初版は、開始時の成績が高い人に緩やかな補正を付ける方式を推薦する。**

長期研究には成長曲線と公開データがあり、将来の成績を予測する既存の式もある。ただし、研究対象は大会選手や特定のトレーニングプログラムの利用者である。「全種目・全体格・初心者から上級者まで、1〜12カ月の成長を公平に採点する」係数は、この調査で確認した研究からは確定できなかった。

初版の係数はアプリの競争ルールとして公開する。科学的に検証された公平な指標とは表示しない。実際の増加kgも併記し、使用感と記録が集まってから見直せる設計にする。

## 3. 公開資料を実際に確認した結果

### 3.1 既存の成長予測式

Ferrariの出版社の[補足Excel](https://media.springernature.com/original/springer-static/esm/art%3A10.1186%2Fs40798-025-00903-z/MediaObjects/40798_2025_903_MOESM6_ESM.xlsx)を取得し、セルの係数と数式を確認した。

年齢・体重等を固定すると、式の時間に関する部分は「定数 ＋ c × ln(時間)」と整理できる。ベンチの時間係数は、丸めて次の形になる。

```text
c = 12.9691 − 1.6864×性別 − 0.118598×年齢
    − 0.0208312×体重 − 3.31707×初大会の相対筋力

性別：男性0、女性1（元研究の符号化）
相対筋力：初大会のベンチ成績kg ÷ その時の体重kg
```

これは新しく推定した係数ではなく、公表された式の時間項をまとめたもの。開始時の相対筋力が高いほど時間係数は小さくなる。ただし、現在の成績を「初大会の成績」に置き換えると別の使い方になる。

元論文のベンチの将来成績RMSEは10.41kg。80:20のランダムな記録分割が記載されているが、選手単位の分離や未来の期間を保留する検証は本文から確認できない。同じ選手の記録が両側に入る可能性を残す。高いR²が、個人の増加kgの高精度な予測を意味するとは限らない。

元記事は[CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)で公開されている。上記の式はFerrariほかの係数から時間に関する項だけをまとめ、表示用に丸めたもの。

Excelの時間入力にも注意が必要。初年のLog_timeは0、次年は約3.8712（ln(48)）で、本文の「週の自然対数」だけでは初大会のゼロや年から週への変換が完全には説明されない。アプリにそのまま移植する前に確認が必要。

### 3.2 大会記録の独自の探索的分析

[Latellaの公開研究プロジェクト](https://osf.io/23qth/)で示された2021年8月4日の[OpenIPFデータ](https://osf.io/download/ruwda/)を取得した。元ファイルは1,026,089行・約210MB。元研究の再現実験ではなく、アプリの用途に近い「次の大会までに何kg伸びたか」を別途調べた。

条件：Raw、SBD、Open部門、Tested=Yes、3種目すべて成功。同じ選手・同じ日の重複は合計成績最大の1行に整理。3大会以上の選手を残した。連続する大会間隔28〜400日、開始年齢18〜60歳、体重30〜200kgを分析した。

- 抽出後の大会記録：45,811件、9,215人。
- 分析対象の間隔：22,721件、6,545人。
- 学習：4,577人・15,881間隔。評価：重複しない1,968人・6,840間隔。
- 学習時は記録が多い選手だけが支配しないよう、選手ごとの合計重みを揃えた。評価指標は間隔ごとの等重み。

開始時の重量÷体重、年齢、体重、性別、初大会からの期間、大会間隔と交互作用を使った簡易回帰を作った。対象は筋肉量の増加ではなく、大会の筋力成績の変化。

| 種目 | 将来成績のR² | 増加kgのR² | 増加kgのRMSE | 実際の増加kgの中央値 |
| --- | ---: | ---: | ---: | ---: |
| ベンチ | 0.964 | 0.035 | 8.80kg | 2.5kg |
| スクワット | 0.944 | 0.037 | 14.79kg | 5.0kg |
| デッドリフト | 0.938 | 0.015 | 15.22kg | 5.0kg |

**将来の重量が当たりそうに見えても、増加量はあまり説明できなかった。** ベンチでは「次も同じ重量」と予測するだけでも将来成績のR²は0.961だった。この結果は、既存論文の予測式が無価値という意味ではない。今回の簡易モデルの結果であり、別のモデルで改善する余地はある。

大会間隔180〜365日の記録では、男性の開始相対筋力の下位25%群のベンチ増加中央値は5kg、上位25%群では0kg。女性では3.75kgと2.5kgだった。集団として開始水準による差はあるが、年齢・経験・体重変化・平均への回帰を分離した因果効果ではない。繰り返し記録も含むため、係数を直接逆算しない。

簡易モデルのベンチ予測増加量は評価標本の約24.7%で0以下になった。「実際の増加量÷予測増加量」はゼロ除算、符号逆転、小さな分母による過大な加点を起こし得る。現在の初版への採用は見送る。

この集団は、成功した大会に繰り返し出場する選手が対象。ベンチの開始重量が体重の0.6倍未満の間隔は163件しかなく、40kgから始める一般利用者の代表集団とは言いにくい。初心者、離脱者、失敗した大会、怪我、プログラム、食事等を十分に表さない。氏名＋性別の識別にも限界がある。一般利用者への外部検証はしていない。

### 3.3 トレーニング研究の抽出Excel

[Pellandの公開プロジェクト](https://osf.io/6z3xu/)の[Extracted Data.xlsx](https://osf.io/download/86g9r/)を取得した。確認時のファイルは710行、そのうち筋力の群・アウトカム行は490行。個人490人という意味ではない。

筋力行の期間中央値10週、最大32週。経験年数は約69%の行で欠落。開始・終了の値と体重は多くの行にあるが、測定種目・単位・プログラムが混在している。ファイルには69の筋力study番号があり、最終論文の67研究・2,058人と一致しないため、採否を再確認せずに論文の解析標本として扱わない。

「Bench Press 1RM」の正の開始・終了値を持つ群を単純にまとめると、経験者43群の成長率中央値約9.7%（期間中央値8週）、未経験者15群は約10.3%（同6週）。この差は期間もプログラムも揃えた比較ではなく、研究の重複や群の依存もある。ここから「初心者は経験者の何倍伸びる」という補正は作らない。

## 4. 初版に推薦する式

### 4.1 開始成績による緩やかな補正

```text
成長ポイント = 100 × (終了成績 − 開始成績) / 種目の基準値 × 補正倍率

補正倍率 = (開始成績 / 種目の基準値)^0.5
```

記号で書くと、`P = 100 × (E − B) / R × sqrt(B / R)`。

- B：開始時の対象種目の成績。
- E：終了時の同じ条件による成績。
- R：対戦開始前に固定する、その種目で共通の配点基準。例としてベンチ60kgを使う。平均筋力や限界重量を表す数字ではない。
- 0.5：高い開始成績への加点を緩やかにする、競争ルール上の仮係数。論文から推定した値ではない。
- 初版では倍率を例えば0.5〜2.0の範囲に制限する案を併せて検討する。上限・下限も競争ルールであり、科学的な閾値ではない。

開始水準が2倍なら、同じ増加kgへの加点は約1.41倍になる。小さな上級者の成長を評価しつつ、開始重量だけで勝敗が決まりにくい程度の補正にする。

これは「本来伸びるべき量の達成率」ではなく、開始水準に応じて配点を変えるアプリ独自の指標。体重、性別、年齢、経験、休止からの再開はまだ補正しない。異なる体格も考慮したい場合は追加設計が必要。

### 4.2 ベンチの例（R=60kg、倍率の制限にかからない範囲）

| 開始→終了 | 増加kg | ポイント |
| --- | ---: | ---: |
| 40→60kg | 20kg | 27.2 |
| 80→100kg | 20kg | 38.5 |
| 40→50kg | 10kg | 13.6 |
| 80→90kg | 10kg | 19.2 |
| 120→125kg | 5kg | 11.8 |

増加0なら0点、低下したらマイナス。同じ種目・同じ対戦では、Rを変えても倍率の制限にかからなければ順位は変わらず、点数の尺度が変わる。Rを変えて結果を調整しない。

### 4.3 ほかの案との比較

| 方式 | 長所 | 初版での判断 |
| --- | --- | --- |
| 増加kgのみ | 説明しやすい | 開始水準を補正できない |
| 増加率 `(E−B)/B` | 体格差の一部を抑えやすい | 同じ20kgなら40→60の方が高得点になり、今回の意図に合いにくい |
| 開始水準に応じた平方根補正 | 透明で、少ない入力で計算できる | 推薦する初版候補。補正の強さはルールとして決める |
| 実増加量÷予測増加量 | 平均的な伸びを超えた程度を評価できる | 予測誤差とゼロ付近の分母の問題が大きい。履歴と検証が必要 |
| 条件付き成長分布のパーセンタイル | 予測平均で割らず、同じ開始条件の人の中で比較できる | 将来候補。十分なデータと分布の校正が必要。成長0でも0点にならない |
| DOTS・Wilks・筋力の百分位の変化 | 絶対筋力の体格補正を使える | 成長の期待値や難易度を直接補正した式ではない |

## 5. 将来、データから式を育てるなら

研究に沿った候補は、成長を対数比 `g = ln(E/B)` として、種目・開始水準・開始体重・経験・期間からその分布を推定する方法。

```text
期待成長 = f(種目、開始成績、開始体重、経験、年齢、期間)
補正スコア = 100 × F(実際の成長 | 同じ開始条件・期間)
```

Fは条件付き成長分布の累積確率。50点は同じ条件の参考集団の中央値、80点は約80%を上回る成長という解釈になる。集団・期間が違えば別のモデルになる。正規分布を仮定するなら `100×Φ((g−μ)/σ)` と書けるが、σは平均の標準誤差ではなく個人の成長を予測する分布の広がりを使う。正規性も検証する。

期間のモデル候補には `a×ln(1+T/τ)` や、経験期間tを入れた `a×ln((τ+t+T)/(τ+t))` がある。ゼロで対数が発散しない形にできる。ただしa・τを勝手に科学的係数として設定せず、データから推定する。大会歴を筋トレ経験に置き換えることも再検証する。

選手・利用者単位の分割、将来期間を保留する評価、外部集団での評価を行う。重量そのもののR²より、増加kgの誤差、期間別・開始水準別の偏り、順位の安定性を重視する。少人数の身内の記録だけで精密な係数を推定せず、同じ人の多数のセットを独立人数として数えない。

期間中に本人が選んだ頻度・セット数で点数を自動補正すると、工夫や継続による成果まで取り除くことになる。まずは開始時点で固定した情報を補正に使い、トレーニング内容はグラフとの照合・振り返りに使う。

## 6. 式より先に揃える測定・対戦ルール

1. **評価する成績を固定する。** 同じ回数での重量、実測1RM、推定1RMは別の指標。初版の式はどれでも計算できるが、対戦の途中で切り替えない。安全に行える普段の記録を使う場合も、同じ器具・動作・可動域・余力の条件を揃える。
2. **推定1RMを使う場合の有効セットを決める。** 現アプリはベンチ・一般種目に `重量×(1+回数/40)`、スクワットに `/33.3` を使っている。通常セットの値を真の最大筋力と見なさず、高回数や余力の違いを順位の根拠にしない。対象回数、代表セットの選び方、1回の実測値の扱いを別途決める。
3. **開始記録の扱い。** 要望の「設定後の最初のトレーニング」を維持する場合、その日のどのセットを成績にするか決める。軽いウォームアップを開始成績にしない。最近の履歴との大きな食い違いは確認できるようにする。
4. **期間と締切。** 種目ごとの1〜12カ月は暦の月で定める。同じ対戦の参加者は開始測定の期限と締切を揃える。記録のない人を0成長として処理しない。
5. **期間が違う成績を直接合算しない。** 短期の伸びを12倍して年間の伸びに換算しない。成長は直線とは限らない。
6. **総合順位。** 初版は種目ごとの順位を基本とする。複数種目の生ポイントを単純に足すと種目の配点尺度に影響される。同じ参加者・種目構成で、順位ポイントの平均など別の総合ルールを決める。
7. **推移グラフ。** 初版のB、R、指数、倍率制限を固定し、各トレーニング日の成績をEとして同じ式を適用する。開始日は0点。カレンダーと照合できるが、グラフだけで方法の因果効果を断定しない。
8. **式のバージョン。** 対戦開始時の式を結果発表まで固定する。次の対戦から係数を改訂し、過去の順位を後から変えない。記録修正の履歴も残せる設計にする。

## 7. 今回保存したもの

- この調査資料。
- `growth_analysis_results.json`：公開データの集計・探索的モデルの評価。アプリ利用者の個人データは含まない。
- `inspect_growth_sources.py`：公開表・補足Excel・OSF一覧の取得と確認用。
- `analyze_growth_data.py`：公開データの探索的分析用。アプリの採点処理ではない。

取得した大きな元データと補足ファイルはWindowsの一時フォルダ `web_app_growth_research_20261007` に保存した。アプリのDBは読み書きしていない。集計JSONに元データURL・容量・SHA-256を記録した。将来ファイルが更新された場合は、同じハッシュのデータで再分析する必要がある。

再分析にはNumPy、pandas、openpyxlがあるPythonを使う。`inspect_growth_sources.py` は小さい補足資料を取得する。OpenIPFの約210MBのCSVは[公開ファイル](https://osf.io/download/ruwda/)を同じ一時フォルダへ `openipf-2021-08-04.csv` として保存した後、`analyze_growth_data.py` を実行する。
